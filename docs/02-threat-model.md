# 02 · 威胁模型与假设

> 对应需求文档 Phase 2 第 1 节。基于 **AegisFlow**（AI-Native 零信任行为检测与自动化响应平台）。

---

## 1. 要防御的攻击链（ATT&CK 映射）

我们选取「高权限账号失陷 + 内网横向」这一真实高频场景作为主防御场景：

| 阶段 | 战术 (ATT&CK) | 攻击者行为 | AegisFlow 对应检测信号 |
|------|---------------|------------|------------------------|
| 1 初始访问 | **TA0001 Initial Access** (T1078 Valid Accounts) | 窃取高权限账号凭证，从异常设备/地域登录 | `new_device`、`new_geo`、`distinct_geo_last_24h` |
| 2 凭证访问 | **TA0006 Credential Access** (T1110 Brute Force / T1110.001) | 口令喷洒 / 撞库 | `failed_logins_1h`、`login_rate_1m` |
| 3 取证(地理) | **TA0001** (T1078.002) | 不可能地理转移（跳跃速度超物理上限） | `impossible_travel_mins` |
| 4 权限提升 | **TA0004 Privilege Escalation** (T1548) | 提权、可疑命令行落地 | `priv_escalation_flag`、`suspicious_cmdline` |
| 5 执行 | **TA0002 Execution** (T1059) | 执行业务外进程、脚本 | `unique_child_procs_1h`、`proc_launch_rate_1h` |
| 6 横向移动 | **TA0008 Lateral Movement** (T1021.001) | 向多台主机扩散 | `lateral_moves_1h` |
| 7 命令控制 | **TA0011 Command & Control** (T1071) | 规律性 C2 回连心跳 | `network_beacon_ms` |

**设计闭环**：检测引擎输出与 ATT&CK 战术阶段绑定（见 `detection/explain.py` 的 `_FEATURE_META`），
每一个告警都能映射到战术链，供分析师与 `docs/06` 的合规映射复用。

## 2. 系统的信任边界

```
        ┌─────────────── 外部不可信区 ───────────────┐
        │  攻击者 / 恶意流量 / 失陷账号 / 被入侵的端点  │
        └───────────────┬────────────────────────────┘
                        │ TLS 1.3 (传输中加密)
   ┌────────────────────▼───────────────────────────┐
   │               Data Plane (采集/边界)             │
   │   每个采集器身份由 mTLS 证书证明，禁止隐式信任      │
   └────────────────────┬───────────────────────────┘
                        │ 双向 mTLS (内部通信，所有组件互证)
   ┌────────────────────▼───────────────────────────┐
   │          Control Plane (检测/决策)               │
   │   AI 模型 / 规则 / 归因 —— 所有决策必须可解释     │
   └───────────────┬──────────────┬─────────────────┘
                   │ mTLS          │ mTLS
   ┌───────────────▼───┐   ┌──────▼──────────────────┐
   │ Management Plane  │   │ 数据存储(静态 AES-256-GCM)│
   │ UI/API/RBAC/ABAC  │   │ 审计哈希链 / 事件库        │
   └───────────┬───────┘   └──────────────────────────┘
               │ 外部 KMS（Vault/AWS/阿里云）—— 密钥不落应用
```

- **信任最低化**：没有任何组件凭「网络位置」被信任；一切内部调用需 mTLS 证书互证。
- **控制平面与数据平面隔离**：检测决策不直接接触外部原始流量；数据平面只收归一化（已脱敏）信号。

## 3. 最坏情况假设（对抗性思考）

AegisFlow 按以下最坏假设设计，确保单点被攻破不导致整体失守：

1. **AI 模型被投毒**：
   - 缓解：模型只接收已脱敏/归一化特征（不含明文 PII）；基线学习器有样本下限 `min_samples`
     与时间窗老化，异常输入难以瞬间改写分布；规则护栏（确定性）与 AI 评分**双通道**，AI 被投毒
     时规则仍能拦住高置信攻击；模型训练与部署隔离开，模型文件经签名校验。
2. **核心节点被攻破**：
   - 缓解：节点无状态（可随时替换）；支付降级；关键动作需 mTLS 身份 + RBAC/ABAC 双重授权；
     所有动作写入哈希链审计（不可抵赖）。
3. **管理员是内鬼**：
   - 缓解：管理员操作同样哈希链留痕（`AuditChain`），且字段级权限让单角色无法越权读取全量 PII；
     KMS 主密钥在外部，管理员不掌握明文密钥。
4. **攻击流量超过容量（DoS/洪峰）**：
   - 缓解：背压（高水位阻塞/丢旧保新）+ 熔断（下游故障快速失败）+ 批量缓冲，**优雅降级而非崩溃**
     （见 `bus/resilient_queue.py`）。
5. **密钥泄露**：
   - 缓解：静态密钥经 KMS 信封，业务侧只持引用；文档明确生产必须用外部 KMS，本地 KMS 仅演示。

## 4. 威胁建模方法论

- 采用 **STRIDE** 逐类核对：Spoofing（mTLS）、Tampering（哈希链+认证加密）、Repudiation（审计链）、
  Information Disclosure（字段级 ABAC+PII 脱敏）、Denial of Service（背压/熔断）、Elevation（RBAC+ABAC）。
- 信任边界已在第 2 节刻画，边界上每个口子都配了对应控制。

---

## 5. 残留风险与说明

- 零外部依赖的 demo 加密构造（`crypto.py`）**仅用于教学/测试**；生产必须切换为 OpenSSL/
  `cryptography` 的标准 AES-256-GCM 后端（接口不变）。这是文档明确的工程边界。
- 本地 KMS 仅演示；生产对接 Vault/AWS/阿里云 KMS（接口已在 `KMSFactory` 预留）。
