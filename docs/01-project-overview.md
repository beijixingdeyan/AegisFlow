# 01 · 项目缘起、方向提案与创新定位

> 对应需求文档中的 **Phase 1：威胁洞察与提案**。先给出 3 个完全不同方向的安全项目
> 提案，再论证为什么选定其中一个（AegisFlow），并点名对比主流产品。

---

## 一、三个方向提案

### 提案 A：AegisFlow —— AI-Native 零信任行为检测与自动化响应平台【**最终选定**】

- **中/英文名**：守护之流 / AegisFlow
- **一句话定位**：以混合 AI 检测引擎为核心、把海量告警收敛为少数高优先事件的下一代 SOC 平台。
- **真实攻击场景**：攻击者窃取某高权限员工账号，凌晨从新设备 + 新地域登录，随后短时高频失败
  登录（撞库）并出现「地理上不可能转移」，最终在端点提权并开始横向移动。传统 SIEM 会生成数千条
  割裂告警；AegisFlow 通过行为基线把「账号行为偏离」识别出来，LLM 推理把断裂信号关联成一条攻击链，
  并在可信范围内自动撤销会话、隔离主机。
- **目标用户画像**：SOC 分析师（减负/降噪）、CISO（风险可见 + 合规）、DevSecOps（自动化响应）、合规官（审计）。
- **核心创新机制**：行为基线 + 多维异常评分 + LLM 因果推理的**混合检测架构**；可解释输出；渐进式自主响应；智能降噪。
- **点名对比**：
  - vs **Splunk ES / QRadar**（规则/关联 SIEM）：AegisFlow 不靠预定义关联规则，而是对未知、新颖攻击有泛化能力，且自带可解释层；Splunk/QRadar 是「高级日志检索 + 规则」，面对未知攻击失效、且告警爆炸。
  - vs **Darktrace**（AI 异常检测）：Darktrace 是着名的黑盒，难以解释、难以通过合规审计；AegisFlow 主打「每个决策可解释」与「由外部 KMS/审计链支撑的合规友好」。
  - vs **CrowdStrike Falcon / 端点检测**：它们聚焦端点，AegisFlow 是跨端点+身份+云+网络的**统一行为视图**，且更强调可部署在私有/混合/纯 SaaS 三种模式下的解耦架构。
- **为什么现有产品解决不好**：业界要么「规则准确但噪音大、对未知无效」，要么「AI 黑盒不可审计」。AegisFlow 同时满足**解释性**与**泛化性**，并解决「安全拖慢业务」与「告警疲劳」两个软性痛点。
- **AI 嵌入点**：检测决策链的核心环节（异常融合后的因果推理、归因、处置建议），非「后加聊天框」。
- **技术风险与可行性**：8/10（行为基线与异常检测成熟；LLM 推理需精心提示/降级策略，本仓库提供了 mock→http 降级。）
- **商业模式**：混合（订阅 + 按量计费 EPS + 企业 License）。

---

### 提案 B：供应链 SBOM 持续信任引擎（Supply-chain Trust Mesh）

- **一句话定位**：面向 DevSecOps/供应链安全，对每个依赖与构件自动生成 SBOM、持续比对漏洞库与策略的持续信任平台。
- **核心创新**：把「一次性漏洞扫描」变为「运行时持续信任评分」，并与 CI/CD 门禁、运行时 SBOM 清单绑定。
- **点名对比**：vs Sonatype Nexus Lifecycle / Snyk / Anchore：这些偏「扫描器+库对比」；提案 B 强调**运行时 SBOM 溯源 + 信任衰减 + 策略即代码**，并解决「扫描器不覆盖运行时新引入的构件」的盲区。
- **可行性**：7/10。方向好但竞争激烈、差异化更窄，故未选为主轴。

---

### 提案 C：隐私计算 + 联邦威胁情报共享节点（Federated Threat-Intel）

- **一句话定位**：让不同机构在不共享原始告警的情况下，联合训练威胁检测模型、共建迄今最全的联邦威胁情报。
- **核心创新**：联邦学习 + 差分隐私 + 可验证的秘密共享，实现「情报不落地也能共用」。
- **点名对比**：vs MISP（情报分享平台）/ Splunk: **MISP 是直接交换 IOCs**；提案 C 不交换原始 IOCs，而是交换**模型梯度/统计**，保护各家数据主权。
- **可行性**：6/10（联邦学习工程复杂、跨机构激励难设计）。

---

## 二、为什么选 A

1. **硬性约束全面命中**：AegisFlow 的架构天然满足高可用/多活/水平扩展/背压熔断/mTLS/审计链/字段级权限等所有约束。
2. **创新约束满足**：它不是「换皮 X」，而是把 AI 嵌入检测核心（行为基线+异常+LLM+可解释），这是明确被禁止项之外的真创新。
3. **商用与 ROI 可量化**：能明确计算「节省分析师工时」「缩短 MTTD/MTTR」，且有渐进式采用路径（先做 Identity 行为检测，再扩端点/云）。
4. **代码可落地**：本仓库已经实现核心引擎并可运行验证（见 08-performance）。

## 三、AegisFlow 的差异化价值主张（对照「禁止项」）

| 禁止的主轴 | AegisFlow 的替代立场 |
|---|---|
| 简单日志收集+仪表盘 (ELK) | 行为基线 + 异常检测 + LLM 推理，**不是展示日志** |
| 传统 SIEM 关联规则 | 混合 AI 检测，规则仅作确定性护栏，非主轴 |
| 传统 IDS/IPS 规则 | 从“规则”升级为“行为模型”，规则作为辅助 |
| 传统 WAF/漏洞扫描/蜜罐 | 不在此方向 |
| 后期加 AI 聊天框 | AI 嵌入检测决策链核心，带可解释 |

AegisFlow 的核心可被一句话概括：**“把分析师的判断力，变成系统可解释、可审计、可自主执行的模型。”**
