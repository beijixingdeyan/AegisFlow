## 1. 等保 2.0 / 等保 3.0 对应条款

| 等保控制点 | 要求 | AegisFlow 对应实现 |
|------------|------|--------------------|
| 身份鉴别 | 双因子、唯一标识 | mTLS 双向认证 + 角色身份（`security/mtls.py`） |
| 访问控制 | 最小权限、角色授权 | RBAC + ABAC + 字段级脱敏（`security/access.py`） |
| 安全审计 | 审计记录、防篡改 | 不可篡改哈希链审计（`security/audit.py`），覆盖管理员 |
| 通信传输 | 加密传输 | TLS 1.3 / 双向 mTLS |
| 数据完整性 | 防篡改、校验 | 认证加密 AES-256-GCM + 哈希链校验 |
| 数据保密性 | 存储加密 | 静态 AES-256-GCM + 外部 KMS 信封 |
| 集中管控/安全运维 | 统一管理 | 管理平面 API + 策略+审计统一视图 |
| 恶意代码防范/检测 | 入侵检测 | 混合 AI 检测引擎（行为基线+异常+LLM） |
| 应急响应 | 自动化响应 | 渐进式自主响应编排（`response/`） |

**等保 3.0 演进**：以 AI 检测、自动化响应、隐私增强作为「新技术风险」的加强项，
正好契合 AegisFlow 的 AI/自动化/零信任能力。

## 2. ISO/IEC 27001 与 SOC 2 Type II 准备路径

### ISO 27001（信息安全管理体系）
- **A.5 信息安全方针 / A.8 资产管理**：SBOM 生成（供应链可审计）、资产清点。
- **A.9 访问控制**：RBAC/ABAC、最小权限、离职回收。
- **A.10 密码学**：AES-256-GCM + KMS 密钥生命周期管理。
- **A.12 操作安全**：背压/熔断/监控、防恶意软件、日志审计。
- **A.18 符合性**：等保/个保法映射文档化。

### SOC 2 Type II（服务组织）
- **安防原则（Security）**：mTLS、静态/传输加密、审计。
- **可用性（Availability）**：Active-Active、健康探活、灾备 RPO/RTO。
- **保密性（Confidentiality）**：字段级脱敏、PII 数据最小化、访问审计。
- **隐私（Privacy）**：PII 采集即脱敏/最小化，配合 GDPR 与个保法处理。

**准备路径**：① 文档化（本仓库 docs）② 技术控制落地（已实现核心）③ 内部审计演练
④ 外部认证评审（SOC 2 Type I → Type II 观察期 6 个月）。

## 3. GDPR / 个人信息保护法（PIPL）数据处理方式

- **数据最小化**：Data Plane 归一化即剥离 PII 字段（`Normalizer._redact` 删除
  `username/sso_email/source_ip/user_agent/hostname/device_id/...`），检测模型只接收数值特征。
- **合法处理基础**：安全运营为「正当利益/法定义务」；PII 仅在必要时少量保留并加密。
- **数据主体权利**：可响应访问/删除请求 —— PII 最小化 + 可追溯审计使该义务落地。
- **跨境传输**：私有化/混合模式默认数据不出客户边界；SaaS 版需 DPA + 合规评估。
- **留存与删除**：审计链可配置留存策略；敏感 detail 字段用 AES-256-GCM 密封（`AuditChain`）。

## 4. 供应链安全（SBOM / 无已知高危 CVE 组件）

- 零第三方依赖的核心（纯标准库），显著降低供应链攻击面。
- 可选依赖（ml/web/test）在 `pyproject.toml` 显式声明，便于生成 SBOM。
- 文档承诺：生产引入任何依赖前生成 SBOM 并比对 CVE 库；不允许已知高危 CVE 组件进入。
